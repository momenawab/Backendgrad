# Deploying SafeSight backend to Render

## What's already wired up
- `render.yaml` — Blueprint defining the web service + a free Postgres DB.
- `build.sh` — installs CPU-only torch, deps, runs `collectstatic` + `migrate`.
- `config/settings.py` — reads `DATABASE_URL` (Postgres), serves static via
  WhiteNoise, auto-trusts the Render hostname, and resolves the PPE model path
  relative to the project (no more hardcoded `/Users/...`).

## Steps
1. Push this repo to GitHub (already done: `momenawab/Backendgrad`).
2. In the Render dashboard: **New → Blueprint**, pick this repo. Render reads
   `render.yaml` and creates the `safesight-backend` web service and
   `safesight-db` Postgres instance.
3. First deploy runs `build.sh` (this is slow — torch + dlib compile).
4. Create your admin user once the service is live:
   Render dashboard → service → **Shell** → `python manage.py createsuperuser`.

## Environment variables (auto-set by render.yaml)
| Var | Value |
|-----|-------|
| `DATABASE_URL` | from the Postgres instance |
| `SECRET_KEY` | generated by Render |
| `DEBUG` | `False` |
| `PYTHON_VERSION` | `3.11.10` |
| `WEB_CONCURRENCY` | `1` |

Add manually if needed:
- `CORS_ALLOWED_ORIGINS` — comma-separated, only if you serve a Flutter **Web**
  build (mobile apps don't need CORS).

## Important caveats
- **Plan size:** the ML stack (torch + face-recognition/dlib) will not fit the
  free 512 MB instance. `render.yaml` requests `standard` (2 GB). Inference is
  CPU-only and slow.
- **dlib build:** `face-recognition` compiles `dlib` during build. If the build
  fails on dlib, pin a version with a prebuilt wheel or add a system cmake step.
- **WebSockets:** uses `InMemoryChannelLayer`, so keep `WEB_CONCURRENCY=1`
  (single process). To scale, switch to `channels-redis` + a Render Redis.
- **Free Postgres** expires after 90 days — upgrade the DB to keep data.

## Flutter app change
Point the app's base URL at `https://<your-service>.onrender.com`, and
WebSocket URLs at `wss://<your-service>.onrender.com` (note `wss`, not `ws`).
Increase HTTP timeouts a little to tolerate cold starts (~30–60 s after idle).
